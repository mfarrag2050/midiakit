# apps/dashboard — أداة تطوير محلّية

**قيد استعمال حاسم — يُقرأ قبل أيّ لمس أو نقل أو نشر:**

هذه اللوحة **أداة تطوير محلّية** (dev tool). تعمل على `127.0.0.1:19030`
عبر Next.js في وضع التطوير.

## القيود البنيوية

1. **صفر مصادقة.** لا session, لا token, لا platform-auth-guard. أيّ
   من يفتح `http://127.0.0.1:19030/ops` يرى كل الطوابير والمهام
   والمقاييس **عبر كل المستأجرين**.

2. **تقرأ عبر المستأجرين من `@pf-mediakit/renderer/observe`** مباشرة
   في نفس عملية Next.js — لا تمرّ بـmk-api ولا بـplatform-auth.

3. **مقصورة على الميني (الشبكة المعزولة، مطوّر واحد).** لا nginx، لا
   بورت public، لا خطّة نشر.

## لا تُنشَر

نشرها في production بلا مصادقة = **خرق أمني كامل** (تسريب مقاييس
عبر المستأجرين). التصميم الحالي لا يمنع تشغيل `next build && next start`
لكنه يمنع بنيوياً وجود مسار قراءة ثانٍ عبر حارس
`check-observe-import-scope`.

## البديل الإنتاجي

`/v1/platform/ops/*` على mk-api (بُنيَ في A25):
- خلف `platform-auth-guard` (A27)
- يستعمل `control_plane_user` pool
- سياسات `control_plane` على جداول المصدر
- يستهلك نفس `observe.ts` — مصدر واحد، طبقتان (dev tool + محروس)

## إن ظهرت خطّة نشر

**عندها** — لا قبل — يُبنى:
1. مصادقة (login + platform-auth)
2. بوابة بناء إنتاجي (الخيار A في تذكرة A25) — تفشل `next build` بلا
   env flag صريح
3. تحويل استدعاء observe إلى fetch على `/v1/platform/ops/*`
