# 465 — نسخ PostgreSQL واستعادة مقيسة

2026-09-24 · التنفيذ مقيس على dev فقط؛ بانتظار حكم §٦ قبل commit.
سجل مسار API العام: [PHASES-api.md](../../PHASES-api.md).

- مصدر التفريغ `migration_user@127.0.0.1:19041/mediakit`؛ يُقرأ الاعتماد
  من `packages/db/.env` (`DATABASE_URL`) في الذاكرة ويُمرّر إلى `pg_dump`
  عبر `PGPASSWORD` فقط. قيم `PGHOST/PGPORT/PGUSER/PGDATABASE` المخالفة تُرفض.
- عند رفض صلاحية التفريغ فقط، يعمل البديل المأذون: `postgres` داخل
  `postgres-dev` عبر Unix socket و`bin/mk`. هذا هو المسار الذي نجح في القياس.
  الإنشاء والاستعادة والبصمات والحذف داخل الحاوية أيضاً؛ لا قراءة أو تصدير
  لكلمة سر الإدارة، ولا اتصال إداري بمنفذ المضيف، ولا تغيير للأدوار.
- `pnpm --dir apps/api backup:pg` ينشئ custom archive مضغوطاً افتراضياً
  في `apps/api/backups/`، ومعه JSON للبصمات. النسخة والبصمات من لقطة
  واحدة، والملفان بصلاحية `0600`. يحتفظ بهما معاً؛ لا حذف تلقائي للنسخ.
- `pnpm --dir apps/api verify:pg-restore` يستعيد آخر نسخة منشورة في قاعدة
  مؤقتة على المثيل نفسه، ويقارن `COUNT(*)` وبصمات MD5 مرتبة بالمفتاح
  الأساسي لجداول `public`. ملف البصمات إلزامي، وتُفحص SHA-256 للنسخة.
  جدول بلا مفتاح أساسي يوقف النسخ/التحقق، ولا يُتجاوز.
- المحاولة الأولى تحتاج `pg_dump` محلياً في PATH. إذا نجحت وكان إصدارها
  الرئيسي أحدث من الخادم، يُرفض نشر النسخة؛ يلزم عميل متوافق مع `pg_restore`
  داخل الحاوية. البديل المأذون لنقص الصلاحية يستخدم أدوات الخدمة نفسها.
  يحتاج التشغيل Docker على سياق `colima-mediakit` والخدمة القائمة؛ لا إشعال
  خدمات أو تبديل سياق. تُنسخ النسخة إلى `/tmp` داخل الحاوية قبل الاستعادة،
  ويُحذف ملفها في finally مستقلة عن محاولة حذف قاعدة الاختبار.
- القياس: 28/28 جدولاً متطابقاً، 23251 صفاً مجموعاً، خروج 0؛ العينة
  `mediakit-2026-09-24T16:15:30.424Z.dump` حجمها 2290521 بايت.
- `--inject-corruption` يعدّل أول tenant بترتيب id في قاعدة الاستعادة
  فقط؛ كشف تغيّر tenants وإضافة revisions من مشغّل التدقيق، خروج 1.
  `--pause-before-cleanup` معه يتيح قياس SIGINT بعد كشف التلف وقبل finally.
- SIGINT المقيس خرج 130؛ finally حذف قاعدة الاختبار وملف النسخة داخل الحاوية.
  قائمة القواعد بعده بلا تطابق (`psql=0`, `grep=1`). حذف القاعدة فعله
  السكربت صراحةً؛ انقطاع اتصال PostgreSQL وحده لا يحذف قاعدة دائمة.
  لم يُقس SIGKILL أو انقطاع الكهرباء أو الإشارة أثناء pg_restore.
- **جدولة مقترحة فقط:** cron يومياً 03:00 بتوقيت الميني لتشغيل
  `node apps/api/scripts/pg-dump.mjs` مع PATH لـNode 20.18.1 وpg_dump وDocker؛
  سطر crontab الكامل في تقرير 465. لم يُثبّت cron أو launchd.

هذه مقارنة بيانات جداول public ببصمات، وليست إثبات تطابق ملفات PostgreSQL
الفيزيائية أو اختبار استعادة مثيل جديد بأدواره أو استعادة S3/Redis.
السكربتان أداتا تشغيل يدوي/جدولة مقترحة؛ لا تدخلان سلسلة الاختبارات العامة.
