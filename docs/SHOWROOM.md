# docs/SHOWROOM.md — بيئة العرض

> **من هي؟** بيئة مستقلّة عن التطوير، يراها الشريك أو العميل. تُشغَّل
> على وسمٍ مسمّى — لا على فرع يتحرّك. **الشريك يرى شيئاً واحداً له
> اسم ثابت** — إن سأل «ماذا أنظر إليه الآن؟» فالجواب: `show-YYYYMMDD-N`.
>
> **النطاق المزمَع (لاحقاً، ليس اليوم):** `mk.primeflow.co`. اليوم:
> `http://127.0.0.1:19071` على جهاز المالك فقط، بلا نفق ولا فتح منفذ.

---

## §1 · الفصل الكامل عن التطوير

بيئة العرض تعيش في worktree منفصل: `~/MediaKit/pf-mediakit-show`،
ولها وحدها:

| المورد | التطوير | العرض |
|---|---|---|
| قاعدة البيانات | `mediakit` (`:19041`) | **`mediakit_show`** (`:19062`) |
| Redis | `redis://127.0.0.1:6379/3` | **`redis://127.0.0.1:19063/0`** |
| Bucket تخزين | `mk-assets-dev` | **`mk-assets-show`** |
| MinIO API | `:19043` | **`:19064`** |
| MinIO console | `:19044` | **`:19065`** |
| API HTTP | `:19040` | **`:19070`** |
| Studio HTTP | `:19050` | **`:19071`** |
| ملفّ الأسرار | `apps/api/.env` | **`.env.show`** (جذر الـworktree، خارج git) |
| بادئة docker | `pf-mediakit-` | **`pf-mediakit-show-`** |

**اختبار الفصل:** اكسر جدولاً في قاعدة التطوير (`DROP TABLE ...`) →
تحقّق أنّ الشريك على `:19071` لم يتأثّر. إن تأثّر — الفصل مكسور.

---

## §2 · النقل بالوسم لا بالفرع

الفرع (`main`) يتحرّك تحت قدمَيك — الوسم لا. النقل إلى العرض:

1. تختار `<sha>` من `origin/main` يفي بشروط §3.
2. `bin/mk show promote <sha>` → يُنشئ وسماً باسم `show-YYYYMMDD-N`،
   ينقل worktree العرض إليه، ويُسجّل الوسم السابق للتراجع.
3. `bin/mk show up` → يُشعل الخوادم على الوسم الجديد.
4. تكتب في تقرير النقل: **أيّ وسم · من أيّ SHA · وما الذي تغيّر
   للشريك** بلغةٍ يفهمها غير المبرمج.

**التراجع بأمر واحد:** `bin/mk show rollback` → يعود إلى الوسم السابق.

---

## §3 · شروط النقل — مكتوبة لا بالحدس

**لا يُنقَل** الالتزام (SHA) الذي يخلّ بواحدٍ منها:

### (أ) خضراء كاملةً في CI

`pnpm test` + verifiers الـ20 خارج السلسلة (خطوة «20 verifier» في
`.github/workflows/ci.yml`) **كلّها خضراء** على SHA بعينه في CI.
مصدر الحقيقة: صفحة Actions للـcommit في GitHub — لا يُقبَل تشغيل
محلّيّ بديلاً.

### (ب) مشية العرض (`120-DEMO-WALK`) — **مؤجَّلة**

الشرط الأصليّ في تذكرة الـshowroom: «مشية العرض عند mkst تمرّ بلا كسر».
حاليّاً **الأداة غير موجودة** (`scripts/verify-demo-walk.mjs` = صفر
نتائج). سلوك مؤقّت:

- **قبل هبوط الأداة:** يُتخطّى هذا الشرط صراحةً في تقرير النقل («شرط
  ب مؤجَّل حتّى تهبط mkst 120-DEMO-WALK»). لا يُعتبر إخفاقاً.
- **بعد هبوطها:** يُصبح شرطاً لازماً — نقلٌ بدون تنفيذها كذبٌ صريح.

### (ج) لا عطبٌ فعّالٌ معروفٌ في مسار العرض

قائمة العطب المفتوح في `PHASES.md` — إن كان أحدها على مسار الشريك
(دخول · إنشاء مشروع · رندر · تحميل) — **لا نقل** حتّى يُغلَق.

### (د) تقرير النقل مكتمل

في `claude/reports/SHOWROOM-<tag>.md`:
- الوسم الجديد · SHA الأصل · تاريخ + توقيت.
- الوسم السابق (للتراجع).
- **بلغةٍ يفهمها غير المبرمج:** ماذا رأى الشريك جديداً؟ ماذا اختفى؟
- شهادة CI (رابط run في GitHub).

## §4 · الأوامر

```bash
bin/mk show up               # يُشعل postgres/redis/minio + migrate + seed + API + Studio
bin/mk show down             # يُطفئ (البيانات في volumes تبقى)
bin/mk show promote <sha>    # وسم جديد + نقل + يبقيك جاهزاً لـup
bin/mk show rollback         # عودة للوسم السابق (يوقف الخوادم تلقائياً)
bin/mk show status           # الوسم · الالتزام · هل الخوادم حيّة
bin/mk show logs api         # tail -f apps/api log
bin/mk show logs studio      # tail -f apps/studio log
bin/mk show seed             # (يدويّاً) إعادة seed — يتخطّى إن كان الحساب موجوداً
```

**متطلّبات:** `docker context show` == `colima-mediakit`. غير ذلك ⇒
السكربت يتوقّف بتعليمات التصحيح.

## §5 · الحساب والأسرار

- **الحساب الوحيد ابتداءً:** `mk@primeflow.co` — المالك، هو أوّل من
  يُسمح له بالدخول.
- **كلمة المرور:** يولّدها `bin/mk show up` عشوائياً عند أوّل seed،
  **تُطبَع مرّةً واحدةً** في stdout لينسخها المالك ويغيّرها من الاستوديو.
  **لا تُلتزم لأيّ ملفّ**، ولا في seed مُلتزَم، ولا في تقرير.
- **الأسرار التسعة** (`SESSION_JWT_SECRET · PLATFORM_JWT_SECRET ·
  AI_KEY_ENCRYPTION_KEY · POSTGRES_ROOT_PASSWORD · MIGRATION_USER_PASSWORD
  · APP_USER_PASSWORD · CONTROL_PLANE_USER_PASSWORD · MINIO_ROOT_USER
  · MINIO_ROOT_PASSWORD`): تُولَّد بـ`openssl
  rand` في `bin/mk-show up`، تُحفَظ في `.env.show` (`.gitignore`d عبر نمط
  `.env*`). خاصّة ببيئة العرض وحدها — **لا كلمات dev/test/production
  إطلاقاً**. أدوار قاعدة الشوروم تُنشأ في
  `infra/postgres/init-show/01-roles.sh` بالكلمات المولَّدة (منفصل عن
  `infra/postgres/init/` المشترك مع التطوير). قرار
  `_AMEND-SHOWROOM-PORTS §3`.
- **قائمة السماح:** يبدأ الحساب وحده. بريد الشريك يُضاف يدوياً من
  الاستوديو حين يعطيه المالك.
- **preflight للمنافذ:** `bin/mk show up` يفحص المنافذ الستّة قبل ربطها.
  إن كان أيّ منفذ مشغولاً (بأيّ عمليّة، dev أو غيره) يتوقّف برسالة تسمّي
  المنفذ ومَن يشغله. **رفض صريح لا اصطدام صامت** (`_AMEND-SHOWROOM-PORTS §2`).
- **`bin/mk show reset`:** يحذف `.env.show` + volumes لبدء نظيف — يُستعمل
  عند upgrade من إصدار قديم من `.env.show`.

## §6 · البذرة — ما فيها

- **1 مستأجر:** «وكالة العرض التجريبيّة» (بلا اسم مؤسّسة حقيقيّة).
- **1 حساب مالك:** `mk@primeflow.co` بدور `owner`.
- **1 brand_kit:** ألوان + خطوط افتراضيّة (Almarai/Inter) — قابلة
  للتعديل من الاستوديو.
- **3 مشاريع تجريبيّة:** بعناوين مُختلَقة (لا محتوى عميل).

البذرة `idempotent` — إعادة `bin/mk show up` لا تُنشئ حساباً ثانياً.

## §7 · ما لا نفعله في هذه المرحلة

- **لا `cloudflared`.**
- **لا تعديل جدار حماية.**
- **لا فتح منفذ خارج الشبكة المحلّيّة.**
- **لا مشاركة أسرار الإنتاج.**

النفاذ الخارجيّ خطوةٌ تالية بيد المالك — تبدأ بتسجيل دخولٍ يملكه هو
وحده.

## §8 · اختبار الحياة (L-46)

قبل الاعتماد على البيئة، أثبت الحياة الثلاث:

1. **إشعال** — `bin/mk show up` من وسمٍ على `main` ⇒ افتح
   `http://127.0.0.1:19071` وسجّل الدخول.
2. **عزل** — احذف جدولاً في قاعدة التطوير (`docker exec
   pf-mediakit-postgres-dev psql -U postgres -d mediakit -c 'DROP TABLE
   projects CASCADE'`) ⇒ تحقّق أنّ الشريك على `:19071` **لم يتأثّر**.
3. **تراجع** — `bin/mk show promote <sha2>` ثمّ `bin/mk show
   rollback` ⇒ تحقّق أنّ الوسم الأوّل عاد كما هو.

هذا اختبارٌ يُنفَّذ عند أوّل نقلٍ فعليّ — لا عند بناء الأدوات فقط.
