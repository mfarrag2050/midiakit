# 02 — المعمارية

## المبدأ الحاكم

```
الإخراج = قالب (Template) + هوية (Brand Kit) + محتوى (Content) + مقاس (Size)
```

أربع طبقات منفصلة تماماً. القالب يقول *"شارة أعلى اليمين"*، الهوية تقول *"لونها كذا وخطها كذا"*، المحتوى يقول *"نصها كذا"*، المقاس يقول *"على 1080×1920"*.

المحرك لا يعرف أن هناك واجهة.

## البنية

```
mediakit/
├─ packages/
│  ├─ engine/          محرك الرسم الخالص — لا DOM، لا localStorage، لا globals
│  │   ├─ text/        cvParseTokens, wrapAlternating, layoutBalanced, drawLineRTL
│  │   ├─ layers/      image, gradient, badge, headline, source, logo, accent
│  │   ├─ render.ts    renderFrame(template, brand, content, size, ctx)
│  │   └─ timeline.ts  drawAt(ctx, W, H, T) — دالة خالصة من الزمن إلى إطار
│  ├─ templates/       تعريفات JSON + مُتحقق schema
│  └─ shared/          أنواع TypeScript مشتركة
├─ apps/
│  ├─ studio/          Next.js — الواجهة، المعاينة الفورية عبر OffscreenCanvas
│  ├─ renderer/        Node worker — skia-canvas + FFmpeg
│  └─ api/             REST/tRPC — المستأجرون، الهويات، المشاريع، الحصص
└─ infra/              Docker, migrations, seeds
```

## الحزمة التقنية

| الطبقة | الاختيار | السبب |
|---|---|---|
| الرندر | Canvas 2D API | تطابق بكسلي بين المعاينة والتصدير |
| المحرك | TypeScript خالص | يعمل في المتصفح وNode بنفس الكود |
| المتصفح | `OffscreenCanvas` | معاينة دون حجب الواجهة |

| البيانات | PostgreSQL | مستأجرون، هويات، مشاريع، حصص |
| الملفات | S3 / R2 | خطوط، شعارات، صور، مخرجات |
| الطوابير | BullMQ + Redis | مهام الفيديو والدفعات |

## قرارات معمارية (ADR)

### ADR-001 — البقاء على Canvas 2D
**القرار:** لا انتقال إلى HTML/CSS للرندر.
**السبب:** منطق `wrapAlternating` (سطر طويل / سطر قصير بنسبة 0.6) وموازنة السطرين بأقل فرق عرض لا يمكن التعبير عنهما في CSS. إعادة بنائهما بـ HTML تستغرق أشهراً وتنتج جودة أدنى.
**المرفوض:** Satori / Puppeteer + HTML — يعطيان مرونة تصميمية لكن يفقدان السيطرة على القياس النصي.
**المقايضة:** كل قالب جديد يحتاج تعريف JSON دقيق بدل CSS مرن.

### ADR-002 — المحرك خالص من الآثار الجانبية
**القرار:** دوال الرسم لا تلمس `document` ولا `localStorage` ولا متغيرات عامة.
**المشكلة الحالية:** الكود يقرأ من الواجهة **داخل** الرسم:
```js
const allBold = document.getElementById('cvAllBold').checked;
const gp = cvGradParams();      // يقرأ من slider
const mul = cvVidTextMul();     // يقرأ من slider
```
هذا الجدار الوحيد بين الأداة والمنتج: يمنع الرندر على الخادم، ورندر هويتين بالتوازي، والاختبار الآلي.
**كذلك يُزال:** `cvCtx`, `CVW`, `CVH` كمتغيرات عامة تُستعاد يدوياً بـ `try/finally`.

### ADR-003 — القوالب بيانات
**القرار:** كل قالب ملف JSON بطبقات وقيود ومراجع إلى الهوية (`brand.colors.urgent`).
**السبب:** يحوّل "إضافة قالب لعميل" من مهمة مبرمج إلى مهمة مصمم. هذا هو الفرق بين خدمة قابلة للتوسّع وأداة تحتاج مطوّرها في كل طلب.

### ADR-004 — الرندر على الخادم للفيديو
**القرار:** استبدال `MediaRecorder` + `captureStream` برندر إطار بإطار.
**عيوب الحالي:**
- يسجّل بالزمن الحقيقي (فيديو 60 ثانية = 60 ثانية انتظار)
- يُسقط إطارات عند انشغال المتصفح — النتيجة تختلف بين جهاز وآخر
- `video/mp4` غير مدعوم في Safari وFirefox ⇒ العميل يحصل على `.webm` لا يقبله إنستغرام

**البديل:** حلقة `for (let f = 0; f < total*30; f++) drawAt(ctx, W, H, f/30)` ← PNG أو خام ← FFmpeg ← MP4.
**الأصل المتاح:** `cvVidDrawAtT(ctx, W, H, T)` في الكود الحالي **دالة خالصة من الزمن إلى إطار بالفعل**. أنت على بُعد خطوة واحدة من رندر احترافي دون تغيير منطق الرسم.

### ADR-005 — الخطوط مسؤولية العميل
**القرار:** لا خط تجاري في المستودع. مجموعة مفتوحة افتراضية (IBM Plex Sans Arabic, Almarai, Tajawal, Cairo, Noto Kufi Arabic) + رفع العميل لخطه المرخّص مع إقرار ملكية في الشروط.
**فائدة مزدوجة:** يزيل المسؤولية القانونية، ويعطي كل عميل هويته الحقيقية — وهو بالضبط ما يدفع مقابله.

### ADR-006 — تحميل الخطوط ديناميكي مع انتظار الجاهزية
**القرار:** `FontFace` لكل هوية، مع `await document.fonts.ready` **قبل أول `measureText`**.
**السبب:** القياس بخط غير محمّل يعطي عروضاً خاطئة فتنكسر السطور بشكل عشوائي — وهو خلل يصعب تتبعه لأنه يظهر ويختفي حسب سرعة الشبكة.
**الحالي:** `cvEnsureFontsThenRender` يحمّل اسماً ثابتاً واحداً (`HNArabic`) — لا يكفي لتعدد الهويات.

### ADR-007 — مشترك افتراضياً، مخصص كطبقة تسعير
**القرار:** خادم مشترك + طوابير بأولوية + حصة عادلة. الخادم المخصص يُباع كطبقة تسعير لا يُبنى كمعمارية افتراضية.
**المرفوض:** خادم لكل عميل — تكلفة خطية باستغلال تحت 2%، وعبء تشغيل مضاعف، ولا يحل الذروة داخل العميل الواحد.
**التفصيل الكامل في ملف 08.**

### ADR-008 — أنبوب مباشر بدل إطارات على القرص
**القرار:** `skia-canvas → Buffer → FFmpeg stdin`. لا ملفات مؤقتة.
**السبب:** يزيل ~6GB مؤقتة لكل فيديو، ويُخرج القرص من عنق الزجاجة، فيصبح التوازي مفيداً (`concurrency = floor(cores/2)`).
**تصحيح:** قرار سابق فرض `concurrency: 1` بحجّة تنافس القرص — كان مبنياً على افتراض الملفات المؤقتة.

**استثناء (ملف 10):** مشاريع الخط الزمني تحتاج **فك ترميز مسبق** إلى إطارات على القرص، لأن القفز العشوائي داخل ملف مضغوط بطيء جداً مع عدة مصادر متزامنة. الأنبوب يبقى للتجميع النهائي؛ القرص يعود للمرحلة الأولى فقط، بكتابة تسلسلية لا عشوائية. لذلك `edit` بعامل واحد وقرص 500GB.

### ADR-009 — موقع الخادم قرار أداء لا قرار امتثال
**القرار:** يُختار الموقع حسب زمن الاستجابة للجمهور الخليجي — فرانكفورت أو البحرين أو دبي.
**السبب:** المشروع خليجي. إقامة أحد العملاء في أوروبا لا تُنشئ اختصاصاً أوروبياً؛ العبرة بموقع الكيان والجمهور.
**المراجعة:** إن ظهر عميل حكومي أو كيان أوروبي فعلي، يُعاد النظر عندها لا قبلها.

### ADR-010 — النموذج الزمني يُبنى من جديد لا يُوسَّع (2026-09-02)

**السياق:** المرحلة 3.7 تطلبت محرّك خط زمني كامل (مسارات متوازية،
مفاتيح مفتاحية، دوال easing، انتقالات، طبقات صوت). الأداة القديمة تحمل
`cvSegTimeline` — تسلسل مقاطع مسطَّح مع animation array — كافٍ لبطاقة
عاجل من صور ثابتة، عاجز عن مقاطع منزلقة أو صوت مُتزامن أو مسارات نصّية
موازية.

**القرار:** بناء `packages/engine/src/timeline/` كاملاً بمعزل عن
`cvSegTimeline`، مع بوابة تكافؤ **253/253 اختبار** قبل حذف القديم.
النموذج الجديد يحمل: `Track[]` (media · text · audio) · `Keyframe[]`
لكل خاصية قابلة للتحريك · `AudioPlan` منفصلة عن `drawTimelineAt`
(خالصة كوسيط) · ثمانية دوال easing · خمسة انتقالات (crossfade · slide
· wipe · zoom · blurIn).

**البدائل المرفوضة:**
1. **توسيع `cvSegTimeline` بالمسارات الجديدة:** يورث ديون البنية القديمة
   — كل مقطع يحمل حقول animation ثابتة، فكل ميزة جديدة = حقل جديد في
   كل مقطع (انفجار سطح البيانات).
2. **بناء v2 داخل نفس المكان مع flag `useV2`:** يعرّض `drawTimelineAt`
   لفرعين شرطيين، يكسر النقاء الزمني، ويعقّد اختبار التكافؤ.
3. **حذف `cvSegTimeline` وبناء v2 محلّه مباشرة:** يترك المشروع بلا نموذج
   زمني عامل حتى يكتمل v2 (أسابيع) — يخالف قاعدة الخنق التدريجي.

**المقايضة:** حجم كود مضاعف مؤقتاً (~1500 سطر إضافي)، تكلفة مراجعة
أعلى، خطر «drift» بين v1 و v2 (خُفِّف ببوابة التكافؤ الاختبارية).
المكسب: نموذج نظيف قابل للامتداد بدل طبقات patches فوق بنية قديمة.

**شرط الجودة (بوابة الاستبدال — القرار الذي جعله آمناً):** حذف
`cvSegTimeline` سُمح به **فقط بعد اجتياز 253/253 اختبار** في
`timeline/*.test.ts` (نفس المدخلات تعطي نفس المخرجات بايت-بايت في MP4
المُصدَّر عبر `verify-breaking-video.mjs`). سكربت التكافؤ
`verify-timeline-equivalence.mjs` بقي حتى قرار الحذف (2026-09-02) ثم
حُذف — نتيجته موثَّقة في PHASES §المرحلة 3.7. **بلا هذه البوابة، ما كان
لهذا القرار أن يكون آمناً** — كان قفزة في المجهول.

**نتيجة:** v2 مدموج في المرحلة 3.7 (2026-09-02)، v1 محذوف كلياً
(~1000 سطر)، `templateToTimeline` هو الجسر، `snapshots-video/` مرجع
دائم يحرس أن أيّ regression في v2 يُكشَف.

### ADR-011 — عزل المستأجرين عبر PostgreSQL RLS مع FORCE (2026-09-04)

**السياق:** المرحلة 4 تُدخل بيانات مستأجرين متعدّدة إلى قاعدة واحدة —
brand_kits · **revisions (الأخطر: لقطات كل تعديل)** · renders والمخرجات
· assets · projects · templates · workflows · project_state · transitions
· annotations · ai_integrations · subscriptions · usage. **المخاطرة
الجوهرية:** أن تظهر هوية عميل (شعار، ألوان، خطوط، صور، تعليقات) في
مخرج عميل آخر. **لا تحلّها المصادقة** — تحلّها الحماية على مستوى القاعدة
نفسها.

**القرار:** كل جدول يحمل `tenant_id` تحته:
- **`ENABLE ROW LEVEL SECURITY`** — تفعيل RLS.
- **`FORCE ROW LEVEL SECURITY`** — تجعل السياسة تُطبَّق على مالك الجدول
  نفسه. بدونها، أيّ اتصال بصلاحية `OWNER` يتجاوزها فيصير الحاجز وهماً.
- سياسة `USING (tenant_id = current_setting('app.tenant_id')::uuid)`
  على SELECT/INSERT/UPDATE/DELETE.
- **التطبيق يتصل بمستخدم بلا `BYPASSRLS` وبلا ملكية الجداول** — `GRANT`
  محدَّد لا `OWNER`. مستخدمو migration/dev/test/admin منفصلون عن `app_user`.
- **`app.tenant_id`** يُضبَط عبر `SET LOCAL` في كل معاملة، مأخوذاً من
  JWT الموقّع (يُفكّ في `auth/session.ts` الوحيد — راجع القرار المرافق
  للمصادقة الذاتية).
- **مسارات المخرجات موقَّعة بانتهاء صلاحية** (signed URLs من R2/S3) —
  لا معرّفات متسلسلة أو مسارات قابلة للتخمين.

**البدائل المرفوضة:**
1. **فلترة برمجية `WHERE tenant_id = ...`:** بند نسيان واحد = تسرّب.
   الأمان يعتمد على انضباط مطوّر، لا حاجز بنيوي.
2. **RLS بلا FORCE:** مالك الجدول يتجاوزها. أيّ سكربت صيانة أو migration
   يكشف كل شيء.
3. **قاعدة منفصلة لكل مستأجر:** مرفوض في ADR-007 — طبقة تسعير لا
   افتراض معماري.
4. **مزوّد خارجي (Neon branches, Supabase RLS-only):** يخلط الحل
   بالمزوّد. RLS على PostgreSQL خام قابل لكل بيئة نشر.

**المقايضة:** كلفة كتابة سياسة لكل جدول + انضباط اتصالات (مستخدمون
منفصلون لكل غرض). المكسب: **الحاجز في القاعدة لا في الرمز** — يبقى
ساري المفعول حتى مع خطأ برمجي أو migration خاطئ.

**شرط الجودة (G-P4-1 في `docs/17`):** بوابة عزل المستأجرين تُجتاز
**قبل بناء أيّ endpoint**. الاختبار يشمل **كل جدول لا عيّنة**، بترتيب
الخطورة: brand_kits · revisions · renders/assets · projects · templates ·
workflows · project_state · transitions · annotations · ai_integrations ·
subscriptions · usage. **الاختبار السلبي الحاسم (L-46):** إعادة تشغيل
الاختبار بعد إزالة `SET LOCAL app.tenant_id` — يجب أن يفشل فوراً بلا لبس.
بلا هذا الاختبار السلبي، RLS نظرياً فقط.

**نتيجة:** بند A1-A4 في `docs/17-phase4-plan.md` يُبنى يوم 1 من مسار A،
ولا يُفتح أيّ endpoint حتى تُجتاز G-P4-1 على الجداول كاملةً.

## نموذج البيانات (مبدئي)

```
tenants        id, name, plan, created_at
users          id, tenant_id, email, role
brand_kits     id, tenant_id, name, config(jsonb), created_at
assets         id, tenant_id, kind(font|logo|audio), url, license_ack
```

## عزل المستأجرين

كل استعلام مقيّد بـ `tenant_id`. يُفضَّل فرضه على مستوى قاعدة البيانات (Row-Level Security) لا في كود التطبيق، حتى لا يعتمد الأمان على انضباط المطوّر.
